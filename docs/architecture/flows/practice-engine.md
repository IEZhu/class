# Поток: движок практики

> Этап 4 — карточки и cloze; этап 5 — видео и тексты.
> Всё крутится вокруг FSRS: любая практика в итоге пишет `srs_reviews`.
> Видео- и тексто-практика `srs_reviews` пока не пишут — долг D-26.

## Очередь повторений (S4-2)

`GET /practice/queue` — due-карточки по FSRS (`srs_cards.due_at <= now`),
сортировка по просроченности. Карточка у слова появляется вместе со
строкой `user_terms` — и из попапа, и при назначении после урока
(ADR-036).

## Карточки (S4-3)

term → перевод/пример; рейтинг again/hard/good/easy → `srs_reviews` →
пересчёт FSRS (go-fsrs) → новое `due_at` и статус слова в словаре по
карточке: шаги обучения — 2, интервал до недели — 3, до месяца — 4,
дальше — 5 (ADR-036). Страница `/practice/cards`: пробел — оборот,
1–4 — оценка.

## Видео-практика (S5-5, [ADR-038](../decisions.md))

1. Берём «забытые» слова студента (status низкий / lapses высокие / due):
   с карточками FSRS вес — по `srs_cards` (пора повторять, забывания),
   без них — по статусу; или слова из `?words=`.
2. FTS-запрос по `subtitle_segments.tsv` (GIN): цель — лемма и её
   неправильные формы (went → go).
3. Ранжирование видео: **покрытие списка** (доля веса найденных слов),
   при равном — **плотность вхождений в минуту**; произведение отвергнуто
   (ADR-038).
4. Плеер: YouTube iframe embed (youtube-nocookie, IFrame Player API) +
   своя панель субтитров с отметкой строк с целевыми словами и прыжками
   по таймкодам. Панель — тот же `<ClickableText>`.

## Тексты (S5-6, S5-7)

- (а) Поиск готовых (S5-7, [ADR-035](../decisions.md)):
  `GET /practice/texts/search` — свои `generated_texts` и предложения
  Tatoeba с переводом, где есть невыученные слова личного словаря (или
  слова из `words`); выше — где таких слов больше. Предложения — из пула
  по 50 кандидатов на слово (GIN по `lemmas`), покрытие текста — по
  `generated_texts.lemmas`. Страница `/practice/texts`, каждый текст —
  `<ClickableText>`.
- (б) Генерация LLM: промпт {слова, CEFR-уровень из запроса (ADR-030), жанр, длина} →
  **валидатор покрытия** (лемматизация; каждое целевое слово ≥ 2 раз, иначе
  ретрай с перечнем недостающих) → сохранение в `generated_texts` →
  рендер как кликабельный материал.

## Cloze-финал (S4-4, S4-5, [ADR-037](../decisions.md))

- `GET /practice/cloze`: слова студента — сначала карточки к показу, затем
  шаги обучения, затем остальные, до 200 слов страницами; на слово — пункт
  (`cloze_items`), предложение — не больше чем в одном пункте выдачи.
  Слово без нового предложения час не ищется (`cloze_misses`), раньше —
  если появился новый источник; пока запись свежая, слово без пунктов
  места среди 200 слов не занимает.
- Источники предложений: реплики уроков студента (урок слова первым),
  видимые участникам материалы этих уроков, свои сгенерированные тексты,
  Tatoeba; поиск по урокам — по хранимым лексемам под GIN.
- Пропуск = форма целевого слова, которая стоит в предложении ровно один
  раз; дистракторы — слова словаря студента той же части речи (слова
  урока первыми), иначе частые слова; у непохожего ключа (t-shirt, café)
  среди них есть такой же непохожий. LLM-дистракторы (S5-8) — `POST
  /practice/cloze/distractors`, кэш общий, лимит «объясни»; ответ не из
  строчных латинских букв до 24 байт их не получает. Набор вариантов
  у пункта один: с ключом LLM пункты после первого приходят `pending`,
  и их варианты (LLM или, при сбое и лимите, словарь) отдаёт этот запрос;
  время ответа у них — от появления кнопок.
- Страница `/practice/cloze`: варианты (клавиши 1–4) или ввод слова,
  предложение — `<ClickableText>`.
- Результат (`POST /practice/cloze/{id}/attempts`) мапится на
  FSRS-рейтинги:

| Результат ответа | FSRS-рейтинг |
|---|---|
| верно + быстро (выбор ≤ 5 с, ввод ≤ 8 с) | easy |
| верно (ключ термина или любая форма слова) | good |
| неверно | again |

Так тест «проверяет необходимость повторов»: `srs_reviews.source='cloze'`,
график повторений общий с карточками. В график идёт ответ по карточке к
показу и промах по любой; верный ответ раньше показа — только журнал
`cloze_attempts`.
