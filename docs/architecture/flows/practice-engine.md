# Поток: движок практики

> Этап 4 — карточки и cloze; этап 5 — видео и тексты.
> Всё крутится вокруг FSRS: любая практика в итоге пишет `srs_reviews`.

## Очередь повторений (S4-2)

`GET /practice/queue` — due-карточки по FSRS (`srs_cards.due_at <= now`),
сортировка по просроченности.

## Карточки (S4-3)

term → перевод/пример; рейтинг again/hard/good/easy → `srs_reviews` →
пересчёт FSRS (go-fsrs) → новое `due_at`.

## Видео-практика (S5-5)

1. Берём «забытые» слова студента (status низкий / lapses высокие / due).
2. FTS-запрос по `subtitle_segments.tsv` (GIN).
3. Ранжирование видео: **покрытие списка × плотность вхождений в минуту**.
4. Плеер: YouTube iframe embed + своя панель субтитров с подсветкой целевых
   слов и прыжками по таймкодам. Панель — тот же `<ClickableText>`.

## Тексты (S5-6, S5-7)

- (а) Поиск готовых: `generated_texts` / Tatoeba по словам.
- (б) Генерация LLM: промпт {слова, CEFR-уровень группы, жанр, длина} →
  **валидатор покрытия** (лемматизация; каждое целевое слово ≥ 2 раз, иначе
  ретрай с перечнем недостающих) → сохранение в `generated_texts` →
  рендер как кликабельный материал.

## Cloze-финал (S4-4, S4-5)

- Источники предложений: урок (utterances), сгенерированный текст, Tatoeba.
- Пропуск = целевое слово; дистракторы — из того же списка слов
  (LLM-дистракторы — апгрейд S5-8).
- Результат мапится на FSRS-рейтинги:

| Результат ответа | FSRS-рейтинг |
|---|---|
| верно + быстро | easy |
| верно | good |
| неверно | again |

Так тест «проверяет необходимость повторов»: `srs_reviews.source='cloze'`,
график повторений общий с карточками.
